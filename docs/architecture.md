## なぜこの構成か

| 設計判断 | 理由 |
|---------|------|
| LINE 採用 | 日本のメッセージング覇権（90M MAU）。Telegram勢が大半のClawathonで差別化 |
| OpenClaw plugin として実装 | ハッカソン要件 + LLM/adapter/tool pluggability の恩恵 |
| Polygon Amoy testnet | JPYC実績豊富・gas安・toolingが厚い・審査員が知っている |
| MockJPYC | mainnet本番JPYCはtestnetに無いため、ERC20互換mockで模倣 |
| Hardhat | npm完結で3日スコープに最適。Foundryも将来の選択肢として残す |
| viem | ethers.jsより軽量・型強度高。プラグインの依存を薄く保つ |
| マイルストーン型エスクロー | 「自律的に段階解放」の物語が強く、デモで milestone毎にtxを流せる |

## 拡張のしどころ

- **agent鍵の分離**: 現状 `setAgent()` で agent EOA を登録できる。本番ではOpenClaw実行ノードのウォレットをここに紐付け、payerは介在不要に
- **クロスボーダー**: `token` を USDC に切り替えるだけで対応可能（contractは token-agnostic に設計済）
- **複数payer/payee**: 現状1:1。groupcontract は別途追加
- **World ID連携**: createEscrow 時に nullifier を要求して人間性検証
